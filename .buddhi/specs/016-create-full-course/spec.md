## 1. Course Overview & Scope

This specification defines the complete 19-lesson curriculum for **Course 06: AI Agents for Beginners** (`track: "ai-agents-for-beginners"`), the seventh course in Buddhilive Academy's 9-course sequential AI Engineering learning path (`00 python` → `01 ai-for-beginners` → `02 data-science-for-beginners` → `03 ml-for-beginners` → `04 generative-ai-for-beginners` → `05 mcp-for-beginners` → `06 ai-agents-for-beginners` → `07 harness-engineering` → `08 edge-ai-for-beginners`).

Every lesson is grounded 1:1 in its mapped reference directory inside `.ref/ai-agents-for-beginners/ai-agents-for-beginners-main/` (`00-course-setup` through `18-securing-ai-agents`, plus `tests/` smoke-test catalogs). All tutorial prose is authored in the developer-friendly, pragmatic persona of `.agents/skills/my-writing-style/SKILL.md`.

All proprietary Microsoft Foundry, Microsoft Foundry Agent Service V2, Microsoft Agent Framework (`FoundryChatClient` / `AIProjectClient`), Azure OpenAI Service, Azure AI Search, Bing Web Grounding, Azure CLI (`az login` / `DefaultAzureCredential`), Microsoft Project Opal, and Microsoft Foundry Local dependencies are replaced with open-source Python frameworks (`google-genai` SDK with `gemini-2.5-flash`, `gemini-2.5-flash-lite`, and `gemini-embedding-001`, `langgraph`, `pydantic`, `mcp` / `FastMCP`, `chromadb`, `mem0ai`, `cognee`, `browser-use`, `playwright`, `opentelemetry-api`, `opentelemetry-sdk`, `PyNaCl`, `jcs`, `ollama`, `sqlite3`) running on **Google Colab Free Tier** (CPU / T4 GPU) and **Google AI Studio Free Tier** (`GEMINI_API_KEY`).

### User Story 1 - Module 1: Agent Foundations, Frameworks & Core Design Patterns (`Lessons 01–04`) (Priority: P1)

A learner finishing Course 05 (`mcp-for-beginners/22-zava-retail-testing-observability-and-production-optimization`) transitions into Course 06 (`ai-agents-for-beginners`) and completes Module 1 (`Lessons 01–04`):
- **Lesson 01 (`01-course-setup-colab-and-gemini-agent-stack`)**: Grounded in `00-course-setup/README.md` and `00-course-setup/AzureSearch.md`. Configures the zero-cost open-source agent development environment on **Google Colab Free Tier** and local Python 3.12+ virtual environments (`python -m venv venv`); obtains and stores a free **Google AI Studio API Key** (`GEMINI_API_KEY` via `google-genai` SDK using `gemini-2.5-flash` and `gemini-2.5-flash-lite`); sets up open-source drop-in alternatives for vector search (`ChromaDB` + `gemini-embedding-001` replacing Azure AI Search), OpenAI-compatible multi-provider clients (Gemini OpenAI-compatible endpoint, MiniMax 204K-token API, Novita AI open-weight models, and local `Ollama` serving `qwen2.5:7b` / `phi4-mini` replacing Foundry Local), and SSL certificate troubleshooting (`truststore`).
- **Lesson 02 (`02-introduction-to-ai-agents-and-use-cases`)**: Grounded in `01-intro-to-ai-agents/README.md`, `01-python-agent-framework.ipynb`, and `tests/lesson-01-smoke-tests.json`. Defines AI Agents as systems combining an **Environment**, **Sensors**, and **Actuators** with an LLM reasoning core, tools, and short/long-term memory; compares the **7 Types of AI Agents** (*Simple Reflex*, *Model-Based Reflex*, *Goal-Based*, *Utility-Based* maximizing $U(s) = w_{\text{cost}} \cdot C(s) + w_{\text{convenience}} \cdot V(s)$, *Learning*, *Hierarchical*, and *Multi-Agent Systems — Cooperative vs. Competitive*) using a running Travel Booking Agent scenario; identifies when to use AI Agents (*Open-Ended Problems*, *Multi-Step Processes*, *Improvement Over Time*) vs. deterministic scripts; and builds a first random-destination `TravelAgent` with a tool-call loop and smoke-test assertion verifier.
- **Lesson 03 (`03-exploring-ai-agentic-frameworks`)**: Grounded in `02-explore-agentic-frameworks/README.md` and `02-python-agent-framework.ipynb`. Contrasts traditional AI integration (*Personalization*, *Automation*, *Enhanced UX*) with AI Agent Frameworks (*Agent Collaboration & Coordination*, *Task Automation & Management*, *Contextual Understanding & Adaptation*); implements rapid prototyping via **Modular Components** (`@tool` function decorators and parsers), **Collaborative Tools** (chaining a `dataretrieval` agent into a `dataanalysis` agent), and **Real-Time Learning**; and compares **Lightweight Agent SDKs** (code-first agent definitions, function tools, conversation sessions) vs. **Managed Agent Platform Services** (stateful `Thread` and `Message` resources, `create_and_process_run` lifecycle, sandboxed code execution, and managed vector stores) using a restaurant menu host agent (`get_specials`, `get_item_price`).
- **Lesson 04 (`04-ai-agentic-design-principles`)**: Grounded in `03-agentic-design-patterns/README.md` and `03-python-agent-framework.ipynb`. Masters human-centric **AI Agentic UX Design Principles** across three dimensions:
  1. **Agent (Space)**: *Connecting, not collapsing* (bringing people, events, and actionable knowledge together rather than replacing humans) and *Easily accessible yet occasionally invisible* (multimodal, seamless foreground/background & proactive/reactive transitions with transparent background paths).
  2. **Agent (Time)**: *Past* (reflecting on historical state and context), *Now* (nudging more than static notifying with contextual cues), and *Future* (adapting across devices, accessibility needs, and continuous interaction).
  3. **Agent (Core)**: *Embrace uncertainty but establish trust* (clear on/off human control and visible agent status).
  Applies the three implementation guidelines—**Transparency**, **Control** (including customizable verbosity, style, and the ability to forget/delete data), and **Consistency**—to audit and build a human-centric Travel Agent.

**Why this priority**: Establishes the entry bridge from Course 05 (`mcp-for-beginners`), updates `src/lib/curriculum.ts` (`plannedLessonCount: 19`, `runtimeBadges` including `'In-Browser Pyodide'`, and 5 structured syllabus modules), and delivers Module 1 (`Lessons 01–04`) as a standalone MVP slice.

### User Story 2 - Module 2: Tool Use, Agentic RAG & Trustworthy Agents (`Lessons 05–07`) (Priority: P2)

A learner masters tool invocation mechanics, autonomous iterative retrieval, and safety/trust engineering across 3 hands-on lessons (`Lessons 05–07`):
- **Lesson 05 (`05-tool-use-design-pattern`)**: Grounded in `04-tool-use/README.md`, `04-python-agent-framework.ipynb`, and `tests/lesson-04-smoke-tests.json`. Covers the 6 building blocks of the **Tool Use Design Pattern** (*Function/Tool Schemas*, *Function Execution Logic*, *Message Handling System*, *Tool Integration Framework*, *Error Handling & Validation*, *State Management*); walks step-by-step through raw LLM function calling (`get_current_time` with `ZoneInfo` timezones, `function_call` output inspection, and `function_call_output` second-turn synthesis) vs. decorated `@tool` orchestration; connects remote MCP tools over HTTP (`MCPStreamableHTTPTool` discovering `search_web_pages` and `fetch_page_content`); combines **Knowledge Tools** (vector/web search) and **Action Tools** (`fetch_sales_data_using_sqlite_query` + sandboxed Python code execution) for a Contoso sales analytics agent; and enforces **read-only (`SELECT`-only) database permissions** to prevent LLM SQL injection or destructive DDL/DML tampering.
- **Lesson 06 (`06-agentic-rag`)**: Grounded in `05-agentic-rag/README.md`, `05-python-agent-framework.ipynb`, and `tests/lesson-05-smoke-tests.json`. Contrasts static *retrieve-then-read* RAG with **Agentic RAG**—an iterative **maker-checker loop** where the model owns its reasoning process:
  1. **Initial Call & Tool Invocation**: Selecting between vector search (`ChromaDB` + `gemini-embedding-001`), web search, and structured SQL queries.
  2. **Assessment & Query Refinement**: Evaluating retrieved relevance/faithfulness and rewriting failed or malformed queries (including NL2SQL self-correction).
  3. **Memory & State**: Tracking prior retrieval attempts to avoid infinite loops.
  4. **Failure Modes, Diagnostic Tracing & Human Fallback**: Self-correcting on irrelevant hits (inspired by *Self-Refine*, *Reflexion*, and *CRITIC*), respecting domain boundaries, and maintaining explainable audit trails.
- **Lesson 07 (`07-building-trustworthy-ai-agents`)**: Grounded in `06-building-trustworthy-agents/README.md`, `06-system-message-framework.ipynb`, and `06-human-in-the-loop.ipynb`. Teaches how to engineer safe, privacy-preserving agents:
  1. **The 4-Step System Message Framework**: Writing a reusable **Meta System Message** template (*Step 1*), drafting a concise **Basic Prompt** (*Step 2*), synthesizing a structured, high-clarity **Agent System Prompt** with Objective, Key Responsibilities, Tone/Style, and Interaction Rules via an LLM (*Step 3*), and iterating across evaluations (*Step 4*).
  2. **Threat Modeling & Mitigations across 5 Attack Vectors**: *Task & Instruction Manipulation* (input filters + conversation turn limits), *Access to Critical Systems* (least-privilege RBAC + authenticated channels), *Resource & Service Overloading* (per-turn and per-service rate limits), *Knowledge Base Poisoning* (corpus verification + signed ingestion), and *Cascading Errors* (container sandboxing + circuit-breaker fallbacks).
  3. **Human-in-the-Loop (HITL) Approval Gates**: Implementing risk-tiered pre-action approval (`APPROVE` / `REJECT` with revision loops and immutable audit logs) before executing high-stakes tool calls.

**Why this priority**: Equips learners with the three foundational operational capabilities of every real-world agent: calling external tools safely, retrieving grounded knowledge iteratively, and operating within trustworthy guardrails.

**Independent Test**: Open Lessons `05` through `07`, run all 3 `<PythonRunner />` sandboxes (`get_current_time` + Contoso read-only SQLite sales query tool-calling engine with SQL injection guard, Iterative Maker-Checker Agentic RAG loop with query reformulation and NL2SQL self-correction, and the 4-Step Meta System Message generator + 5-Threat Defense Gate + Human-in-the-Loop approval workflow), and verify companion Colab notebooks (`05`–`07`).

**Acceptance Scenarios**:

1. **Given** a learner on Lesson 05 (`05-tool-use-design-pattern`), **When** they run the `<PythonRunner />` sandbox and open `05-tool-use-design-pattern.ipynb`, **Then** the agent parses function schemas, executes `get_current_time` and `fetch_sales_data_using_sqlite_query` against an in-memory Contoso SQLite database, blocks a simulated `DROP TABLE` SQL injection attempt via a read-only SQL guard, and passes the Lesson 04 `TravelToolAgent` smoke test assertions.
2. **Given** a learner on Lesson 06 (`06-agentic-rag`), **When** they run the sandbox and notebook, **Then** the Agentic RAG maker-checker loop detects an under-specified or zero-hit initial query, autonomously reformulates the query across vector search (`ChromaDB`), competitor documents, and SQL sales metrics, synthesizes a grounded answer with source citations, and passes the Lesson 05 `TravelRAGAgent` smoke tests.
3. **Given** a learner on Lesson 07 (`07-building-trustworthy-ai-agents`), **When** they run the sandbox and notebook, **Then** they transform a 2-sentence basic travel prompt into a structured 5-section system prompt via the Meta System Message Framework, block simulated instruction-hijack and resource-overload attacks, and pause high-risk booking/refund actions at a Human-in-the-Loop `APPROVE`/`REJECT` gate.

### User Story 3 - Module 3: Planning, Multi-Agent Systems, Metacognition & Production Observability (`Lessons 08–11`) (Priority: P3)

A learner masters multi-step task decomposition, multi-agent coordination topologies, self-reflective metacognition, and production observability/evaluation across 4 lessons (`Lessons 08–11`):
- **Lesson 08 (`08-planning-design-pattern`)**: Grounded in `07-planning-design/README.md` and `07-python-agent-framework.ipynb`. Decomposes complex goals (*"Create a travel plan for a family of 2 kids from Singapore to Melbourne"*) into strongly typed subtasks using **Pydantic Structured Outputs** (`AgentEnum`: `flight_booking`, `hotel_booking`, `car_rental`, `activities_booking`, `destination_info`, `default_agent`, `group_chat_manager`; `TravelSubTask`; `TravelPlan` with `main_task`, `subtasks`, and `is_greeting`); builds a **Semantic Router & Planner Agent** that routes single-task queries directly and multi-task plans through an orchestrator; and implements **Iterative Re-Planning** (inspired by *Magentic-One*'s task ledger and progress ledger) when mid-flight constraints or user feedback change.
- **Lesson 09 (`09-multi-agent-design-patterns`)**: Grounded in `08-multi-agent/README.md`, `08-multi-agent/solution/solution.md`, `08-multi-agent/solution/solution-quiz.md`, and `08-multi-agent/code_samples/`. Evaluates when to choose a **Multi-Agent System** (*Large Workloads*, *Complex Tasks*, *Diverse Expertise* yielding *Specialization*, *Scalability*, and *Fault Tolerance*) vs. a single agent; masters the 6 multi-agent building blocks (*Agent Communication*, *Coordination Mechanisms*, *Agent Architecture*, *Visibility/Logging/Visualization/Metrics*, *Multi-Agent Patterns*, *Human-in-the-Loop*); implements three core multi-agent patterns:
  1. **Group Chat** (centralized or decentralized turn-taking across specialized agents).
  2. **Handoff** (rule-based state transitions across workflow stages).
  3. **Collaborative Filtering** (combining an *Industry Expert*, *Technical Analysis Agent*, and *Fundamental Analysis Agent* to score and rank stock/travel recommendations).
  Designs both the **15-Agent E-Commerce Refund Topology** (5 process-specific agents: *Customer*, *Seller*, *Payment*, *Resolution*, *Compliance* + 10 general agents: *Shipping*, *Feedback*, *Escalation*, *Notification*, *Analytics*, *Audit*, *Reporting*, *Knowledge*, *Security*, *Quality*) and the **14-Agent Customer Support Assignment Architecture**.
- **Lesson 10 (`10-metacognition-in-ai-agents`)**: Grounded in `09-metacognition/README.md` and `09-python-agent-framework.ipynb`. Teaches how agents "think about their own thinking" across 4 deep technical sections:
  1. **Metacognitive Self-Reflection**: Evaluating why a prior decision failed (e.g., `HotelRecommendationAgent` reflecting that its `'cheapest'` strategy recommended a low-quality hotel (`quality < 7`) and autonomously switching its decision strategy to `'highest_quality'`).
  2. **Goal-Bootstrapped Iterative Planning & Pre-Emptive Context Load**: Pre-loading high-frequency destination knowledge vs. on-demand RAG, and bootstrapping a budget-constrained travel plan ($\sum c_i \le B$) before iteratively swapping items to maximize preference satisfaction.
  3. **Corrective RAG, Relevancy Scoring, LLM Re-Ranking & Search with Intent**: Computing multi-attribute relevance scores $S(d, q)$, re-ranking candidate destinations with Gemini (`google-genai`), and classifying user queries into **Informational**, **Navigational**, and **Transactional** intent combined with user history personalization.

### User Story 4 - Module 4: Agentic Protocols, Context Engineering, Memory & Graph Workflows (`Lessons 12–15`) (Priority: P4)

  1. **Model Context Protocol (MCP)**: Host-Client-Server architecture exposing **Tools**, **Resources**, and **Prompts** for dynamic tool discovery and model-agnostic integration (connecting an agent to an airline MCP server to `search_flights` and `book_flight`).
  2. **Agent-to-Agent Protocol (A2A)**: Cross-organization multi-agent collaboration via **Agent Cards** (JSON metadata advertising agent name, description, skills, endpoint URL, version, and streaming/push capabilities), **Agent Executors** (passing task context to remote agents running their own LLMs), **Artifacts** (structured work products returned upon completion), and **Event Queues** (long-running progress updates across Airline, Hotel, and Car Rental A2A agents).
  3. **Natural Language Web (NLWeb)**: Turning any website into an AI-native surface and MCP server (`ask` method) backed by **Schema.org / RSS ingestion**, **Embedding Models**, and a **Vector Database** so both humans and remote agents can query grounded site catalogs (`"Find me a family-friendly hotel in Honolulu with a pool"`).

  2. **Context Distraction** $\rightarrow$ Fixed via **Rolling Context Summarization & History Reset**.
  3. **Context Confusion** (>30 tools degrading model selection) $\rightarrow$ Fixed via **RAG-Based Dynamic Tool Loadout Management** (retrieving top-$k$ relevant tools per query).
  4. **Context Clash** (contradictory staged instructions, e.g., *"fly economy"* then *"fly business class"*) $\rightarrow$ Fixed via **Preference Pruning & Scratchpad Reconciliation**.
