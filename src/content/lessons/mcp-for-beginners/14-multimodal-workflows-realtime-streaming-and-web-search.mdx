Text-only tools cover a lot of ground, yet modern AI assistants routinely generate charts, inspect screenshots, process audio clips, and pull live search results. MCP handles all of these natively through typed multi-modal content blocks and streaming tool orchestration.

---

## Multi-Modal MCP Content Types

A single MCP `tools/call` response can return a heterogeneous list combining text, images, audio, and embedded resources:

| Content Block Type | Required Fields | Typical Use Case |
| :--- | :--- | :--- |
| **`TextContent`** | `type: "text"`, `text` | Summaries, structured JSON, citations |
| **`ImageContent`** | `type: "image"`, `data` (base64), `mimeType` | Generated charts, screenshots, diagrams sent to `gemini-2.5-flash` vision |
| **`AudioContent`** | `type: "audio"`, `data` (base64), `mimeType` | Synthesized speech or audio clips |
| **`EmbeddedResource`** | `type: "resource"`, `resource: { uri, mimeType, text/blob }` | Attaching a full source file or dataset snapshot inline |

---

## Realtime Streaming & Multi-Tool Web Search Orchestration

When building a **Web Search MCP Server**, splitting capabilities into focused tools (`general_search`, `news_search`, `product_search`, and `qna`) lets the LLM Host pick the exact search backend and schema for the user's intent instead of stuffing every query into one overloaded endpoint.

For high-frequency realtime feeds (stock ticks, sensor logs, live search streams), servers stream chunked updates over Streamable HTTP SSE while applying bounded window buffering so slow clients never cause unbounded memory growth.
