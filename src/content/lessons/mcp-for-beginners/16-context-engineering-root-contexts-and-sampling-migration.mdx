Even the smartest language model fails if you feed it noisy, fragmented, or truncated context. **Context Engineering** is the discipline of selecting, structuring, compressing, and maintaining the exact information an LLM needs at each turn. Because MCP standardizes how tools and resources feed into a model, it is the natural control plane for context engineering.

---

## The 5-Stage Context Journey & 3 Core Principles

Every MCP turn moves through five stages: **User Input** -> **Context Assembly** -> **Model Processing** -> **Response Generation** -> **State Management**.

Three practical principles keep that pipeline reliable:

1. **Share Context Completely**: Fragmenting context across isolated sub-agents produces conflicting assumptions. Keep a shared, consistent context ledger whenever steps depend on prior decisions.
2. **Actions Carry Implicit Decisions**: Every tool call or architectural choice shapes downstream steps; prefer linear, context-aware execution over blind parallel fan-out when decisions compound.
3. **Balance Depth with Window Limits**: Use progressive resource loading (`resources/read` on demand) and semantic pruning instead of dumping entire repositories into the prompt.

### Measuring Context Effectiveness

We can track context quality quantitatively with **Context Utilization Ratio (CUR)**:

$$\text{CUR} = \frac{|C_{\text{cited}}|}{|C_{\text{assembled}}|}$$

A high CUR means the tokens you paid to assemble actually contributed to the final answer rather than acting as distracting noise.

---

## Migrating Legacy `2025-11-25` Root Contexts to `2026-07-28`

In `2025-11-25`, clients used the `roots/list` capability (`file://workspace`) to hint which directories a server should inspect. Because Roots never enforced a security boundary and are **deprecated in `2026-07-28`**, modern servers accept explicit workspace paths as tool parameters or server configuration and enforce strict path-traversal sandboxing (`Path.resolve().is_relative_to(allowed_root)`).

import posixpath

# 1. Greedy value-density context packing within token budget
chunks = [
    {"id": "arch_spec", "tokens": 40, "relevance": 0.95},
    {"id": "auth_rules", "tokens": 35, "relevance": 0.88},
    {"id": "old_logs", "tokens": 50, "relevance": 0.20},
    {"id": "sql_schema", "tokens": 20, "relevance": 0.90},
]
budget = 100
ranked = sorted(chunks, key=lambda c: c["relevance"] / c["tokens"], reverse=True)
packed, used = [], 0
for c in ranked:
    if used + c["tokens"] <= budget:
        packed.append(c["id"])
        used += c["tokens"]

print(f"Packed {len(packed)}/{len(chunks)} chunks (tokens={used}/{budget}): {packed}")
cited = {"arch_spec", "sql_schema"}
cur = len(cited.intersection(packed)) / len(packed)
print(f"Context Utilization Ratio (CUR): {cur:.2f} ({len(cited)}/{len(packed)} packed chunks cited)")

# 2. Modern 2026-07-28 workspace path sandbox (replaces legacy Roots)
ALLOWED_ROOT = "/workspace"
def check_workspace_path(candidate: str) -> str:
    norm = posixpath.normpath(candidate)
    if norm == ALLOWED_ROOT or norm.startswith(ALLOWED_ROOT + "/"):
        return "ALLOWED"
    return "BLOCKED (path traversal)"

for p in ["/workspace/src/app.py", "/workspace/../../etc/passwd"]:
    print(f"Sandbox check '{p}' -> {check_workspace_path(p)}")`}
