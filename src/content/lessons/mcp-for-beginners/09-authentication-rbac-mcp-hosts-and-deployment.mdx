Once your MCP server passes local tests, you need to wire it into real developer hosts (like VS Code, Claude Desktop, Cursor, or Cline) and protect remote HTTP endpoints with **Authentication** and **Role-Based Access Control (RBAC)** before deploying to containers.

---

## Authentication & RBAC Middleware

Think of **Authentication** as showing your photo ID at a building lobby (*"Who are you?"*, returning HTTP `401 Unauthorized` if missing or invalid), and **Authorization / RBAC** as your keycard deciding which rooms you can open (*"Are you allowed to invoke this specific tool?"*, returning HTTP `403 Forbidden` when your role lacks permission).

| Role | Allowed Tool Annotations / Operations | Denied Operations |
| :--- | :--- | :--- |
| **`viewer`** | `readOnlyHint: True` (`list_docs`, `get_status`) | Any write or destructive tool (`create_record`, `delete_record`) |
| **`developer`** | Read tools + non-destructive writes (`create_record`) | Admin or `destructiveHint: True` operations (`delete_record`) |
| **`admin`** | Full access across all tools, resources, and admin configs | None |

In a Starlette or FastAPI remote MCP server, ASGI middleware validates the `Authorization: Bearer <token>` header, attaches the verified role to request context, and blocks unauthorized calls before they ever reach tool business logic.

## Configuring Real-World MCP Hosts

Most popular IDEs and desktop AI clients read a declarative JSON configuration file:

- **VS Code (`.vscode/mcp.json`)**: Supports `inputs` with `"password": true` so API keys are prompted securely at runtime rather than committed to Git:

```json
{
  "inputs": [
    { "type": "promptString", "id": "api-key", "description": "API Key", "password": true }
  ],
  "servers": {
    "my-local-mcp": {
      "type": "stdio",
      "command": "python",
      "args": ["server.py"],
      "env": { "API_KEY": "${input:api-key}" }
    }
  }
}
```

- **Claude Desktop / Cursor / Cline**: Use `"mcpServers"` as the top-level key with `"command"`, `"args"`, and `"env"` for `stdio` servers, or `"url"` for Streamable HTTP endpoints.

### Hardened Container Deployment Checklist

When packaging a remote Streamable HTTP MCP server for cloud deployment:
1. Use a **multi-stage Docker build** with a non-root user (`USER appuser`).
2. Expose `/health` and `/ready` endpoints for orchestrator probes.
3. Inject secrets strictly via runtime environment variables, never `COPY .env`.

## Try It Yourself: RBAC Policy Gate & Multi-Host Config Compiler

Run this pure-Python sandbox to enforce RBAC permissions across `viewer`, `developer`, and `admin` roles and validate a `.vscode/mcp.json` configuration without hardcoded secrets.

**MCP RBAC Gate & Host Config Validator**

```python
import json

ROLE_PERMS = {
    "viewer": {"read"},
    "developer": {"read", "write"},
    "admin": {"read", "write", "delete"},
}
TOOL_REQ = {
    "list_docs": "read",
    "create_record": "write",
    "delete_record": "delete",
}

def authorize_call(token_role: str | None, tool_name: str) -> str:
    if not token_role:
        return "401 Unauthorized"
    needed = TOOL_REQ[tool_name]
    if needed not in ROLE_PERMS.get(token_role, set()):
        return "403 Forbidden (requires admin)"
    return "200 ALLOWED"

print("Missing token ->", authorize_call(None, "list_docs"))
print("viewer calling 'list_docs' ->", authorize_call("viewer", "list_docs"))
print("viewer calling 'delete_record' ->", authorize_call("viewer", "delete_record"))
print("admin calling 'delete_record' ->", authorize_call("admin", "delete_record"))

vscode_mcp = {
    "inputs": [{"type": "promptString", "id": "gemini-key", "password": True}],
    "servers": {"calc-mcp": {"type": "stdio", "command": "python", "args": ["calc.py"], "env": {"GEMINI_API_KEY": "${input:gemini-key}"}}},
}
raw = json.dumps(vscode_mcp)
secret_hygiene = "AIza" not in raw and "${input:" in raw
print(f"Host config valid: secret_hygiene={secret_hygiene}, servers={list(vscode_mcp['servers'].keys())}")
```

**Expected Output:**

```text
Missing token -> 401 Unauthorized
viewer calling 'list_docs' -> 200 ALLOWED
viewer calling 'delete_record' -> 403 Forbidden (requires admin)
admin calling 'delete_record' -> 200 ALLOWED
Host config valid: secret_hygiene=True, servers=['calc-mcp']
```
