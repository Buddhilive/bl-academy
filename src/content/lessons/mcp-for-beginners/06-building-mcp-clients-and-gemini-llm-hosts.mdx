A programmatic MCP client can call `session.list_tools()` and `session.call_tool("add", {"a": 2, "b": 3})`, which is great for scripts and automated tests. Real users, however, want to type a natural-language question and let an AI model figure out which tools to invoke and in what order. That is the job of an **MCP Host Application**.

In this lesson, we wire a Python MCP client directly into **Google AI Studio (`google-genai`, `gemini-2.5-flash`)** so Gemini discovers your MCP server's tools dynamically and orchestrates multi-step tool calls on its own.

---

## Programmatic Client vs. Autonomous LLM Host

| Mode | Who Picks the Tool? | How Arguments Are Built | Best For |
| :--- | :--- | :--- | :--- |
| **Deterministic MCP Client** | Your Python code | Hardcoded or parsed from CLI flags | Automated tests, CI pipelines, batch ETL scripts |
| **Autonomous LLM Host** | `gemini-2.5-flash` | Extracted from user natural language via JSON Schema | Chat assistants, IDE copilots, multi-step agents |

### The 4-Step Host Negotiation Loop

When a user sends a prompt to an MCP Host powered by Gemini:

1. **Discover Capabilities**: The MCP Client calls `list_tools()` on connected MCP servers and converts each MCP `inputSchema` into a `google.genai.types.FunctionDeclaration`.
2. **Reason & Plan**: The Host sends the user prompt plus the converted tool declarations to `client.models.generate_content(model="gemini-2.5-flash", ...)`.
3. **Execute on MCP Server**: If Gemini returns `response.function_calls`, the Host routes each call to the matching MCP Server via `session.call_tool(name, args)`.
4. **Synthesize Grounded Answer**: The Host appends each `FunctionResponse` part back into the conversation and lets Gemini produce the final human-readable answer.

## Translating MCP JSON Schemas for `google-genai`

MCP uses standard JSON Schema `type`, `properties`, and `required` fields. Converting them for `google-genai` is a lightweight mapping function:

```python
from google.genai import types

def mcp_tools_to_gemini(mcp_tools) -> list[types.Tool]:
    declarations = []
    for tool in mcp_tools:
        declarations.append(
            types.FunctionDeclaration(
                name=tool.name,
                description=tool.description or "",
                parameters=tool.inputSchema,
            )
        )
    return [types.Tool(function_declarations=declarations)]
```

Notice how clean that boundary is: the MCP server knows nothing about Gemini, and Gemini knows nothing about `stdio` or HTTP transports. The Host bridges both worlds.
