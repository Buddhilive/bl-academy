Training a model in a notebook is only half the job—eventually, real users need to interact with it through a web or mobile app. In this lesson, we train a multi-class classifier on **80,000 NUFORC UFO sightings** (`Seconds`, `Latitude`, `Longitude` $\rightarrow$ `Country`), serialize the fitted model with Python's `pickle` module, and wire it into both a classic **Flask** web server and an instant **Gradio / FastAPI** interface on Google Colab.

---

## Architecture Choices for Serving ML Models

Before exporting a model, confirm four architectural questions:

| Question | Option A (Server-Side Python) | Option B (Client / Edge / Mobile) |
| :--- | :--- | :--- |
| **Runtime** | `pickle` + Flask / FastAPI / Gradio | ONNX Runtime Web, TensorFlow.js, or TensorFlow Lite |
| **Offline Support** | Requires network call to REST endpoint | Runs locally inside the browser or mobile device |
| **Security Note** | Never un-pickle `.pkl` files from untrusted sources | Export weights as safe tensor formats (`.onnx`, `.safetensors`) |

## Cleaning, Pickling & Serving the UFO Sightings Model

After dropping null rows and filtering sightings between `1` and `60` seconds, we encode the five target countries alphabetically (`0: Australia, 1: Canada, 2: Germany, 3: UK, 4: US`) with `LabelEncoder` and fit `LogisticRegression()`. Because `Latitude` and `Longitude` correlate strongly with geography, the model reaches **~95% accuracy**.

We flatten the model to disk with `pickle.dump(model, open('ufo-model.pkl', 'wb'))`, verify `model.predict([[50, 44, -12]])` returns `[3]` (`UK`), and serve predictions in Flask (`app.py`):

```python
@app.route("/predict", methods=["POST"])
def predict():
    int_features = [float(x) for x in request.form.values()]
    prediction = model.predict([np.array(int_features)])
    countries = ["Australia", "Canada", "Germany", "UK", "US"]
    return render_template("index.html", prediction_text=f"Likely country: {countries[prediction[0]]}")
```

In Google Colab, we can also launch the exact same pickled model with **Gradio** (`gr.Interface`) or **FastAPI** in three lines of code. Notice what makes deployment tricky in production: the web server must pass input features in the **exact same order, scale, and shape** (`[Seconds, Latitude, Longitude]`) that the notebook used during `model.fit()`. Documenting that input contract clearly is what keeps model training and application engineering in sync.
