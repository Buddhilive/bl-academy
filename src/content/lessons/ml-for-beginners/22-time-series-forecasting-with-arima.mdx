**ARIMA** (*AutoRegressive Integrated Moving Average*) is the gold-standard statistical workhorse for univariate time series forecasting. Because electricity load shows strong 24-hour daily cycles and non-stationary drift, we extend ARIMA into seasonal **SARIMAX** (`statsmodels.tsa.statespace.sarimax.SARIMAX`), evaluate it with **walk-forward validation**, and measure accuracy using **MAPE**.

---

## Stationarity, Differencing & SARIMAX Parameters

A time series is **stationary** when its mean and variance stay constant over time. **Differencing** ($\nabla y_t = y_t - y_{t-1}$) removes trends so ARIMA can model stable patterns.

| Parameter | Component Name | What It Controls |
| :--- | :--- | :--- |
| **`p` (AR)** | AutoRegressive | Number of past lag values regressed to predict the current value |
| **`d` (I)** | Integrated | Number of non-seasonal differencing steps applied for stationarity |
| **`q` (MA)** | Moving Average | Number of past forecast error terms included in the prediction |
| **`(P, D, Q, s)`** | Seasonal Order | Seasonal AR, differencing, and MA terms over period $s = 24$ hours |

## Walk-Forward Validation & MAPE

In time series, you must **never** shuffle train and test rows randomly—future observations would leak into the past. We train on `2014-11-01` to `2014-12-29` (`1,416` hours), scale to $[0, 1]$ with `MinMaxScaler`, and test on `2014-12-30` to `2014-12-31` (`48` hours).

Using a 720-hour (30-day) sliding training window and `HORIZON = 3` hours (`load+1`, `load+2`, `load+3`), **walk-forward validation** predicts the next 3 steps, appends the true observation, drops the oldest hour, and repeats. We score forecasts with **Mean Absolute Percentage Error (MAPE)**:

$$\text{MAPE} = \frac{100\%}{n} \sum_{t=1}^{n} \left| \frac{\text{actual}_t - \text{predicted}_t}{\text{actual}_t} \right|$$

Our SARIMAX model achieves **`0.56%` one-step MAPE** and **`1.15%` multi-step MAPE**—a remarkably low error rate considering that a MAPE of $10\%$ means predictions drift by $10\%$ on average. Remember to call `scaler.inverse_transform()` on both `prediction` and `actual` columns in your evaluation DataFrame (`eval_df`) so you interpret errors in real megawatts rather than $[0, 1]$ scaled units. Keep the sliding `training_window` fixed (720 hours) so each walk-forward re-fit stays fast.
