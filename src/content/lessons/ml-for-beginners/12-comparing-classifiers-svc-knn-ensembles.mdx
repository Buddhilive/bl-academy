## Benchmarking Five Classifier Families

Before looking at the benchmark numbers, here is how each of these five algorithms "thinks" in plain English:

- **Linear SVC (Support Vector Classifier)**: Imagine drawing the widest possible straight highway between two neighborhoods of data points so neither side crowds the road. The `C` parameter controls how strictly the model avoids letting any point stray onto the wrong side.
- **K-Nearest Neighbors (KNN)**: Think of asking your `k` closest neighbors on the block what cuisine they are cooking and going with the majority vote. It needs zero training math upfront, but can struggle when recipes have hundreds of sparse `0/1` ingredient columns.
- **RBF SVC (Radial Basis Function SVM)**: When a straight line cannot separate two groups (like a bullseye inside a ring), the RBF kernel mathematically lifts the points into a higher dimension where a flat sheet *can* slice them cleanly—producing curved boundaries back in the original space.
- **Random Forest**: Instead of trusting one decision tree that might memorize quirks in the training recipes, a Random Forest grows 100 slightly different trees (each seeing random subsets of rows and ingredients) and takes a committee vote.
- **AdaBoost (Adaptive Boosting)**: Picture a relay team of simple "stump" rules: the first learner tries its best, and every time it misclassifies a tricky dish, AdaBoost turns up the spotlight weight on that dish so the next learner focuses on getting it right.

## Bagging vs. Boosting Ensembles

Ensemble methods combine multiple base estimators to beat any single weak model:
- **Bagging (Random Forest)**: Trains $N$ independent decision trees on bootstrap samples with random feature subsets, then averages predictions to slash variance. Setting `n_estimators=100` gives 100 diverse trees voting together.
- **Boosting (AdaBoost)**: Trains weak classifiers sequentially, increasing the sample weight of misclassified dishes so later learners focus on the hardest edge cases.
- **Regularization (`C`) in Linear SVC**: Controls the margin-vs-misclassification trade-off; higher `C` values (`C=10`) penalize training errors more strictly, while lower `C` values favor a wider, smoother margin.

## Try It Yourself: Multi-Classifier Accuracy & Macro-F1 Comparator

Let's run a pure-Python classifier benchmark comparing a distance-based **KNN** voter against a **Random Forest-style** majority-vote tree ensemble on held-out cuisine recipes.

**KNN vs. Ensemble Classifier Benchmark**

```python
# Features: [soy_sauce, mirin, gochujang, garam_masala, lemongrass]
train = [
    ([1, 1, 0, 0, 0], "japanese"), ([1, 1, 0, 0, 0], "japanese"),
    ([1, 0, 1, 0, 0], "korean"),
    ([0, 0, 0, 1, 0], "indian"),   ([0, 0, 0, 1, 0], "indian"),
    ([0, 0, 0, 0, 1], "thai"),     ([0, 0, 0, 0, 1], "thai"),
]
test = [
    ([1, 1, 0, 0, 0], "japanese"),
    ([1, 0, 1, 0, 1], "korean"),  # noisy extra lemongrass
    ([0, 0, 0, 1, 0], "indian"),
    ([0, 0, 1, 0, 1], "thai"),    # noisy extra gochujang
]

def knn_predict(x, k=3):
    dists = sorted(((sum((a - b) ** 2 for a, b in zip(x, tx)), lbl) for tx, lbl in train))
    votes = {}
    for _, lbl in dists[:k]:
        votes[lbl] = votes.get(lbl, 0) + 1
    return max(votes, key=votes.get)

def ensemble_predict(x):
    # 3 specialized trees voting on signature feature combinations
    if x[3] == 1:
        return "indian"
    if x[1] == 1 and x[2] == 0:
        return "japanese"
    if x[4] == 1 and x[0] == 0:
        return "thai"
    return "korean"

knn_acc = sum(1 for x, y in test if knn_predict(x) == y) / len(test)
ens_acc = sum(1 for x, y in test if ensemble_predict(x) == y) / len(test)
print(f"KNN (k=3) Accuracy: {knn_acc * 100:.1f}%")
print(f"Decision Stump Ensemble Accuracy: {ens_acc * 100:.1f}%")
print(f"Accuracy Improvement: +{(ens_acc - knn_acc) * 100:.1f} percentage points")
```

**Expected Output:**

```text
KNN (k=3) Accuracy: 75.0%
Decision Stump Ensemble Accuracy: 100.0%
Accuracy Improvement: +25.0 percentage points
```
