You may know that downloading a model from Hugging Face gives you FP16 or BF16 weights where every parameter takes 16 bits. On a 7B model, that is 14 GB before you even type a single word. **Quantization** compresses those weights down to 8, 4, or even 2 bits, and **`llama.cpp`** with the **GGUF** format makes running those compressed weights on CPUs and edge GPUs fast and portable.

Here is an overview of precision tiers, affine block quantization math, and how `llama.cpp` K-quants preserve accuracy.

---

## Precision Tiers & GGUF K-Quants

Practitioners group quantization into three precision bands:
- **Ultra-Low Precision (1–2 bit)**: `Q2_K`, BitNet 1.58-bit; extreme compression for memory-starved hardware, higher perplexity trade-off.
- **Low Precision (3–4 bit)**: `Q4_0`, `Q4_K_M`; ~75 percent size reduction with strong reasoning retention. `Q4_K_M` is the industry workhorse for edge SLMs.
- **Medium Precision (5–8 bit)**: `Q5_K_S`, `Q6_K`, `Q8_0`; ~50 to 65 percent reduction with near-FP16 fidelity.

| GGUF Format | Effective Bits/Weight | 7B Model Size | Quality Retention | Recommended Use Case |
| :--- | :--- | :--- | :--- | :--- |
| **`Q8_0`** | 8.50 bpw | ~7.2 GB | Near-lossless | Accuracy baselines and teacher evaluation |
| **`Q5_K_M`** | 5.69 bpw | ~4.8 GB | Very high | Production coding and JSON function calling |
| **`Q4_K_M`** | 4.85 bpw | ~4.1 GB | High | Default balanced edge deployment |
| **`Q4_0`** | 4.50 bpw | ~3.8 GB | Moderate-high | Legacy CPU SIMD and mobile baseline |
| **`Q2_K`** | 3.35 bpw | ~2.8 GB | Degraded | Extreme RAM-constrained experiments |

## Block Quantization & Super-Block Overhead

In uniform affine quantization, a floating-point weight block $x$ is mapped to $b$-bit integers using scale $s$ and zero-point $z$:

$$
q = \text{clamp}\!\left(\text{round}\!\left(\frac{x}{s}\right) + z,\; q_{\min},\; q_{\max}\right), \qquad \hat{x} = s \cdot (q - z)
$$

Because storing one FP16 scale per 32 weights (`Q4_0`) adds $\frac{16}{32} = 0.5\text{ bpw}$ overhead, **K-quants** (`Q4_K_M`) group 256 weights into a **super-block** and quantize the sub-block scales themselves! The effective bits per weight is:

$$
\text{bpw} = b + \frac{b_{\text{scale}}}{B_{\text{block}}}
$$

And the end-to-end `llama.cpp` conversion workflow takes three commands:

```bash
python convert_hf_to_gguf.py ./phi-4-mini --outtype f16 --outfile phi-4-mini-f16.gguf
./build/bin/llama-quantize phi-4-mini-f16.gguf phi-4-mini-q4_k_m.gguf Q4_K_M
./build/bin/llama-cli -m phi-4-mini-q4_k_m.gguf -p "Explain edge AI briefly." -n 128
```

# Deterministic 32-element weight block
weights = [math.sin(i * 0.45) * 0.8 + math.cos(i * 0.2) * 0.2 for i in range(32)]
signal_power = sum(w * w for w in weights) / len(weights)

def symmetric_block_quant(block, bits):
    q_max = (1 << (bits - 1)) - 1
    max_abs = max(abs(v) for v in block)
    scale = max_abs / q_max if max_abs > 0 else 1.0
    recon = [max(-q_max, min(q_max, round(v / scale))) * scale for v in block]
    noise_power = sum((a - b) ** 2 for a, b in zip(block, recon)) / len(block)
    sqnr_db = 10.0 * math.log10(signal_power / noise_power)
    bpw = bits + (16.0 / len(block))  # 16-bit scale per 32 weights
    reduction = (1.0 - bpw / 16.0) * 100.0
    return bpw, sqnr_db, reduction

for bits in (8, 4, 2):
    bpw, sqnr, red = symmetric_block_quant(weights, bits)
    print(f"Precision={bits}-bit | Effective bpw={bpw:.2f} | SQNR={sqnr:.2f} dB | Size Reduction={red:.1f}%")`}
