## Text Generation Apps vs. Traditional Software

Traditional CLI and GUI applications execute fixed `if/else` control paths. Text generation apps keep deterministic validation around the edges while delegating open-ended language synthesis to an LLM:

| Design Concern | Why It Matters in Production | Implementation Pattern |
| :--- | :--- | :--- |
| **Input Validation** | Untrusted text can inject adversarial instructions or crash downstream parsers | Enforce numeric bounds (`1 <= n <= 10`) and regex character whitelists (`^[a-zA-Z0-9\s,.\-']+$`) |
| **Token & Sampling Control** | Unbounded responses blow latency budgets; high temperature breaks factual tasks | Set `max_output_tokens` and tune `temperature` ($0.0$ for facts, $0.7$ for recipes) |
| **Prompt Chaining** | One massive prompt often drops details on multi-step transformations | Feed Prompt 1's completion (`old_prompt_result`) into Prompt 2 as structured context |
| **Secret Isolation** | Prevents leaking `GEMINI_API_KEY` in shared notebooks or logs | Read from `google.colab.userdata` or `.env` via `python-dotenv` |

## Application 1: Multi-Step Recipe & Shopping List Chainer

Instead of asking a model to invent recipes and calculate a grocery list in one shot, we **chain two LLM calls**:

1. **Stage 1 (Recipe Generation)**: Pass `no_recipes`, `ingredients` already at home (e.g., `chicken, broccoli, carrots`), and `dietary_filter` (e.g., `gluten-free`) to generate recipes with nutritional highlights.
2. **Stage 2 (Shopping List Subtraction)**: Concatenate `old_prompt_result` with `"Produce a shopping list for the generated recipes, and please don't include ingredients that I already have."`

```python
response_1 = client.models.generate_content(
    model="gemini-2.5-flash",
    contents=prompt_1,
    config=types.GenerateContentConfig(temperature=0.7, max_output_tokens=600),
)
old_prompt_result = response_1.text

prompt_2 = (
    f"{old_prompt_result}\n\n"
    f"Produce a shopping list for these recipes, excluding: {ingredients}."
)
response_2 = client.models.generate_content(model="gemini-2.5-flash", contents=prompt_2)
```

## Application 2 & 3: History Bot & Python Study Buddy

- **Historical Persona Bot**: Accepts a `persona` (such as *Abraham Lincoln*) and a `question`. By setting `temperature=0.0` and instructing *"Only state facts accurate to your lifetime; if asked about later events, say you do not know"*, the bot stays in character without fabricating modern opinions.
- **Python Study Buddy**: Answers beginner Python questions using a strict three-part pedagogical contract:
  - `- Concept`
  - `- Example code`
  - `- Explanation`
