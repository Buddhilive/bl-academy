Once you start building Generative AI products, the very first engineering question you hit is: *which model should I actually pick?* There is no single "best" model for every workload. A model that shines at multi-page reasoning may be way too slow or expensive for classifying 10,000 support tickets per minute. In this lesson, we'll break down how to categorize LLMs by modality, Transformer architecture, licensing openness, and output type—and how to climb the 4-tier adaptation hierarchy without over-engineering.

---

## Categorizing the Modern LLM Landscape

Before benchmarking models, it helps to separate **the model** (weights and architecture) from **the service** (the API endpoint, rate limits, safety filters, and caching layer wrapped around it). Models themselves fall into four clear dimensions:

1. **Modalities**:
   - **Text & Code**: Autoregressive reasoning, summarization, and code synthesis.
   - **Audio / Speech**: Automatic speech recognition and transcription (such as Whisper).
   - **Image Generation**: Latent diffusion and text-to-image synthesis (such as Stable Diffusion and Imagen).
   - **Native Multimodal**: Models like `gemini-2.5-flash` that ingest text, images, audio, and video in a single unified Transformer.
2. **Foundation Models vs. Instruction/Chat-Tuned Models**:
   - A **Foundation Model** is trained via self-supervised learning on broad web-scale corpora to predict the next token.
   - An **Instruction-Tuned / Chat Model** undergoes supervised fine-tuning and alignment (RLHF/DPO) so it follows user instructions and dialogue turns instead of just continuing raw text.
3. **Open-Weight / Open-Source vs. Proprietary Hosted Models**:
   - **Open-Weight Models** (Gemma, Llama, Mistral, OLMo) let you inspect weights, run locally, or fine-tune on your own GPU.
   - **Proprietary Hosted APIs** (Gemini, Claude, GPT) deliver frontier reasoning and massive context windows with zero GPU management.
4. **Output Categorization**:
   - **Generative Completions**: Human-readable text, JSON, or code.
   - **Dense Embeddings**: Fixed-length numeric vectors (e.g., `gemini-embedding-001`) powering semantic search, clustering, and RAG.

## Transformer Architectures: Encoder vs. Decoder vs. Seq2Seq

Every Transformer model uses attention, but they wire their attention masks differently depending on the job:

| Architecture | Attention Direction | Mental Model | Representative Models | Ideal Workloads |
| :--- | :--- | :--- | :--- | :--- |
| **Encoder-Only** | Bidirectional (sees left & right context) | The **Reviewer** | BERT, RoBERTa, ModernBERT | Text classification, Named Entity Recognition (NER), embeddings |
| **Decoder-Only** | Causal / Masked (sees only prior tokens) | The **Creator** | Gemini, GPT, Llama, Mistral, Gemma | Chatbots, code generation, reasoning, agentic tool calling |
| **Encoder-Decoder** | Bidirectional encoder + causal decoder | The **Translator** | T5, Flan-T5, BART | Machine translation, structured document summarization |

## The 4-Tier LLM Adaptation Hierarchy

When a baseline model does not yet know your company's internal policies or match your output style, developers often jump straight to fine-tuning. That is usually a mistake. Always climb this ladder from top to bottom:

$$\text{Prompt Engineering} \;\longrightarrow\; \text{RAG (Vector Grounding)} \;\longrightarrow\; \text{Fine-Tuning (LoRA/SFT)} \;\longrightarrow\; \text{Pre-Training from Scratch}$$

- **Tier 1 — Prompt Engineering with Context**: Lowest cost, zero GPU training, instant iteration. Solves formatting, tone, and reasoning structure.
- **Tier 2 — Retrieval-Augmented Generation (RAG)**: Injects fresh, private, or domain-specific documents at query time using vector embeddings. Best when facts change daily.
- **Tier 3 — Fine-Tuning**: Updates model weights on curated examples when you need specialized domain behavior, compact prompts, or strict stylistic consistency.
- **Tier 4 — Training from Scratch**: Reserved for organizations with billions of proprietary domain tokens and dedicated GPU clusters.
