Because Large Language Models generate fluent, confident prose, it is dangerously easy for users to assume every sentence they produce is factually true and ethically neutral. In reality, an unguarded LLM is a statistical next-token predictor—if you ask it a trick question like *"Who was the sole survivor of the Titanic?"*, a naive model will happily invent a name and backstory even though more than 700 passengers survived. In this lesson, we'll examine the core risks of Generative AI and implement a practical **4-layer defense-in-depth architecture** to keep your applications safe, grounded, and trustworthy.

---

## Core Responsible AI Principles & GenAI Failure Modes

Every production Generative AI application should be evaluated against six foundational principles: **Fairness**, **Inclusiveness**, **Reliability & Safety**, **Privacy & Security**, **Transparency**, and **Accountability**. When teams skip these checks, three specific GenAI failure modes surface quickly:

- **Hallucinations / Fabrications**: Generating plausible-sounding falsehoods, fake legal citations, or nonexistent historical events when a prompt implies a false premise.
- **Harmful Content**: Producing hate speech, harassment, self-harm instructions, or dangerous physical guidance when provoked by adversarial users.
- **Bias & Lack of Fairness**: Repeating or amplifying demographic stereotypes absorbed from internet-scale training corpora.

---

## The Measure → Mitigate → Operate Lifecycle

Responsible AI is not a one-time checkbox before launch; it is a continuous engineering loop:

1. **Measure**: Assemble red-teaming prompt sets targeting hallucinations, hate speech, jailbreaks, and demographic bias. Score baseline responses on **accuracy**, **groundedness**, **similarity**, and **relevance**.
2. **Mitigate**: Apply layered technical controls (safety filters, grounded system prompts, and UI constraints), then re-measure against the same benchmark.
3. **Operate**: Monitor live traffic for abuse or drift, maintain clear **incident response and rollback plans**, and log user feedback for continuous auditing.

### The 4 Defense-in-Depth Mitigation Layers

Rather than relying on a single prompt instruction to keep an app safe, production systems stack four independent layers:

| Layer | Responsibility | Concrete Implementation |
| :--- | :--- | :--- |
| **1. Model Layer** | Baseline safety alignment & capability fit | Choose instruction-tuned models aligned with RLHF/DPO and matched to domain risk |
| **2. Safety System Layer** | Automated input/output policy filtering | Configure `google-genai` `SafetySetting` (`HarmCategory` + `HarmBlockThreshold`) and abuse rate limits |
| **3. Metaprompt & Grounding Layer** | Behavioral boundaries & factual anchoring | Inject system instructions (*"Cite only provided sources; correct false premises"*) + RAG retrieval |
| **4. User Experience (UX) Layer** | Calibrated human oversight | Display AI disclosure badges, limit free-form input length, and provide feedback/flag buttons |

## Configuring Gemini Safety Settings in Python

With `google-genai`, you can configure Layer 2 safety thresholds directly on `GenerateContentConfig`:

```python
from google.genai import types

safety_config = types.GenerateContentConfig(
    system_instruction=(
        "You are a careful fact-checker. If a user prompt contains a false premise, "
        "explicitly correct the premise instead of inventing an answer."
    ),
    safety_settings=[
        types.SafetySetting(
            category=types.HarmCategory.HARM_CATEGORY_HATE_SPEECH,
            threshold=types.HarmBlockThreshold.BLOCK_LOW_AND_ABOVE,
        ),
        types.SafetySetting(
            category=types.HarmCategory.HARM_CATEGORY_DANGEROUS_CONTENT,
            threshold=types.HarmBlockThreshold.BLOCK_LOW_AND_ABOVE,
        ),
    ],
)
```
