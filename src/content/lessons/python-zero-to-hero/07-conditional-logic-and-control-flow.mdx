## Introduction to Conditional Logic and Control Flow

In prior chapters, your Python scripts were **unconditional programs**: lines executed strictly in sequence, from top to bottom, one statement after another. While linear execution is suitable for basic arithmetic and predictable transformations, real-world software must adapt dynamically to variable inputs, unexpected user actions, network latencies, and real-time state changes.

Conditional logic transforms programs from rigid sequences into adaptable decision trees. With conditional flow control, your software can:
* Evaluate arbitrary states and select specialized execution branches.
* Recover gracefully from runtime exceptions without crashing the operating system process.
* Interrupt, skip, or finalize loops based on intermediate data discoveries.
* Run probabilistic simulations—such as Monte Carlo experiments—to model complex real-world systems through repeated random trials.

In this chapter, you will master the foundational primitives of Python control flow: boolean comparators, compound boolean operators, branching statements (`if`, `elif`, `else`), fine-grained loop control (`break`, `continue`, `for...else`), exception handling (`try` / `except`), and probabilistic simulation modeling using Python's `random` module.

## 7.1 Comparing Values and Boolean Primitives

Conditional execution fundamentally relies on evaluating expressions that resolve to a **boolean truth value**: either `True` or `False`. In Python, truth values are represented by the built-in primitive type `bool`.

In Python's type hierarchy, `bool` is actually a concrete subclass of `int`:
```python
issubclass(bool, int)  # Evaluates to True
True == 1              # Evaluates to True
False == 0             # Evaluates to True
```

### The Six Boolean Comparators

Python provides six standard relational operators to compare numbers, strings, and other data structures:

| Operator | Mathematical Meaning | Syntax Example | Evaluates To |
| :--- | :--- | :--- | :--- |
| `>` | Strictly greater than | `3 > 5` | `False` |
| `<` | Strictly less than | `"a" < "b"` | `True` |
| `>=` | Greater than or equal to | `1 >= 1` | `True` |
| `<=` | Less than or equal to | `10 <= 5` | `False` |
| `!=` | Not equal to (inequality) | `1 != 2` | `True` |
| `==` | Equal to (value equality) | `1 == 1` | `True` |

```python
# Comparing numerical quantities
age = 18
is_adult = age >= 18
print(is_adult)  # True

temperature = 32.0
is_freezing = temperature <= 32.0
print(is_freezing)  # True
```

### String Comparisons and Lexicographical Order

When using relational operators like `<` or `>` with strings, Python does not compare string length; it compares strings **lexicographically**—evaluating character by character based on each character's underlying Unicode code point via the built-in `ord()` function:

```python
print("a" < "b")  # True, because ord("a") == 97 and ord("b") == 98
print("apple" < "astronaut")  # True: 'a' == 'a', but 'p' (112) < 's' (115)
```

> [!NOTE]
> **Case Sensitivity in Lexicographical Sorting**: In Unicode and ASCII tables, all standard uppercase Latin characters ($65$ through $90$) precede lowercase Latin characters ($97$ through $122$). Consequently:
> ```python
> print("Zebra" < "apple")  # True! ord('Z') is 90, ord('a') is 97
> ```

> [!WARNING]
> **Common Pitfall: `=` vs `==`**: A frequent syntax error among beginners is using a single equals sign (`=`) inside an expression. In Python, `=` is the **variable assignment statement**, whereas `==` is the **equality comparison operator**. Writing `if x = 5:` triggers a `SyntaxError: invalid syntax`.

## 7.2 Combining Logic with Logical Operators

Real-world conditions often depend on multiple criteria evaluated simultaneously. Python provides three core logical operators to construct compound boolean expressions: `and`, `or`, and `not`.

### Truth Rules for `and`, `or`, and `not`

1. **The `and` Conjunction ($A \land B$)**: Evaluates to `True` if and only if **both** operands evaluate to `True`. If either operand is `False`, the compound expression yields `False`.
2. **The `or` Disjunction ($A \lor B$)**: Python implements an **inclusive OR**. It evaluates to `True` if **at least one** operand is `True`. It yields `False` only when both operands are `False`.
3. **The `not` Negation ($\neg A$)**: Inverts the boolean truth polarity of an operand. `not True` evaluates to `False`, and `not False` evaluates to `True`.

The complete boolean truth table is defined as follows:

| Operand $A$ | Operand $B$ | `not A` | `A and B` | `A or B` |
| :--- | :--- | :--- | :--- | :--- |
| `True` | `True` | `False` | `True` | `True` |
| `True` | `False` | `False` | `False` | `True` |
| `False` | `True` | `True` | `False` | `True` |
| `False` | `False` | `True` | `False` | `False` |

### Operator Precedence Hierarchy

When multiple operators appear in a single unparenthesized line of code, Python resolves them according to a strict mathematical hierarchy of precedence (from highest precedence to lowest):

$$\text{1. Relational Comparators } (<, \le, ==, \ge, >, \neq) \quad \succ \quad \text{2. } \mathbf{not} \quad \succ \quad \text{3. } \mathbf{and} \quad \succ \quad \text{4. } \mathbf{or}$$

#### Step-by-Step Expression Evaluation:

Consider the expression:
$$\left(\text{"A"} \neq \text{"A"}\right) \lor \neg\left(2 \ge 3\right)$$

In Python code:
```python
result = ("A" != "A") or not (2 >= 3)
```

1. **Step 1 (Evaluate Comparisons)**:
   * `"A" != "A"` evaluates to `False`.
   * `2 >= 3` evaluates to `False`.
   * Current expression: `False or not False`.
2. **Step 2 (Apply `not`)**:
   * `not False` evaluates to `True`.
   * Current expression: `False or True`.
3. **Step 3 (Apply `or`)**:
   * `False or True` evaluates to `True`.

> [!TIP]
> **Use Defensive Parentheses**: Even when you understand operator precedence, complex expressions like `a and not b or c` increase cognitive load for other developers. Enclosing sub-expressions in parentheses—such as `(a and (not b)) or c`—eliminates ambiguity and prevents subtle logic bugs.

## 7.3 Controlling Program Flow with `if`, `elif`, and `else`

Branching structures allow your code to execute distinct blocks based on runtime conditions. Python uses whitespace indentation (conventionally four spaces) to define code blocks governed by control flow headers.

### 1. The `if` Statement

The `if` statement evaluates a test expression. If the expression evaluates to `True`, the indented block beneath it executes. If `False`, the interpreter skips the block entirely:

```python
score = 85
if score >= 70:
    print("Pass: Minimum proficiency achieved.")
```

### 2. The `else` Clause

The `else` clause provides an exhaustive fallback branch. It executes if and only if the preceding `if` condition evaluates to `False`:

```python
grade = 45
if grade >= 70:
    print("You passed the class!")
else:
    print("You did not pass the class :(")
```

### 3. Multi-Way Branching with `elif`

When choosing between more than two mutually exclusive alternatives, chaining multiple `if` statements is inefficient and error-prone. The `elif` (short for *else if*) statement checks sequential alternatives:

```python
grade = 85

if grade >= 90:
    print("Grade: A")
elif grade >= 80:
    print("Grade: B")
elif grade >= 70:
    print("Grade: C")
else:
    print("Grade: Failing")
```

**Execution Mechanics**: Python tests conditions sequentially from top to bottom. As soon as **one condition evaluates to `True`**, Python executes that specific indented block and immediately exits the entire `if...elif...else` construct, skipping all subsequent branches.

### Refactoring Nested `if` Pyramids

Deeply nested `if` statements create an anti-pattern known as the "arrow anti-pattern" or "pyramid of doom," which obscures program intent. Consider this nested structure:

```python
# Problematic: Deeply nested conditions
if is_enrolled:
    if has_paid_tuition:
        if not on_academic_probation:
            print("Access granted to course materials.")
```

Applying boolean operators like `and` flattens the hierarchy into a clean, single-level guard clause that adheres to Python's core design philosophy (*"Flat is better than nested"*):

```python
# Idiomatic: Flattened compound guard clause
if is_enrolled and has_paid_tuition and not on_academic_probation:
    print("Access granted to course materials.")
```

## 7.4 Practical Challenge: Finding Factors of an Integer

A fundamental mathematical application of conditional logic in loops is calculating the factors of an integer.

### Mathematical Definition of a Divisor

A positive integer $d$ is defined as a factor (or divisor) of a positive integer $n$ if and only if dividing $n$ by $d$ leaves a remainder of zero:

$$n \equiv 0 \pmod d \iff n \pmod d = 0$$

In Python, the remainder of integer division is calculated using the **modulus operator `%`**. If `n % d == 0`, then `d` evenly divides `n`.

### The Factor Finding Algorithm

To determine all factors of an integer $n$:
1. Iterate an integer counter $i$ across the closed interval $[1, n]$ using `range(1, n + 1)`.
2. For each iteration, test whether `n % i == 0`.
3. If the condition is met, output or collect $i$.

The computational complexity of this linear search across all values up to $n$ is linear with respect to the input magnitude:

$$T(n) = \mathcal{O}(n)$$

## 7.5 Loop Control with `break`, `continue`, and `else`

Standard loops execute across every element in a sequence or continue until a while-condition becomes `False`. However, many algorithms require interrupting an iteration early upon discovering target data or skipping invalid records.

### The `break` Statement

The `break` statement halts execution of the innermost enclosing loop immediately. The interpreter jumps directly to the first statement following the loop block:

```python
for n in range(0, 5):
    if n == 2:
        break
    print(n)
# Output:
# 0
# 1
```

When $n = 2$, the condition triggers `break`, terminating the loop entirely before `2`, `3`, or `4` are printed.

### The `continue` Statement

The `continue` statement abandons the remaining statements inside the current iteration's loop body and jumps immediately to the beginning of the next iteration:

```python
for i in range(0, 5):
    if i == 2:
        continue
    print(i)
# Output:
# 0
# 1
# 3
# 4
```

When $i = 2$, `continue` skips the `print(i)` call for that cycle, resuming execution at $i = 3$.

### The `for...else` and `while...else` Construct

In Python, loops can feature an optional `else` block. Unlike an `if...else` branch, the `else` block of a loop executes **only if the loop completes all iterations normally without hitting a `break` statement**:

```python
phrase = "it marks the spot"

for character in phrase:
    if character == "X":
        print("Found target character 'X'!")
        break
else:
    print("There was no 'X' in the phrase.")

# Output:
# There was no 'X' in the phrase.
```

If the string contains `"X"`, the loop triggers `break`, and the `else` block is completely bypassed. If the loop completes without ever encountering `"X"`, the `else` block executes. This Pythonic idiom cleanly eliminates the need for manual boolean flag variables like `found = False`.

## 7.6 Error Handling with `try` and `except`

Errors that emerge while a program is actively running are called **exceptions**. Unhandled exceptions halt execution immediately, unwinding the call stack and displaying a traceback.

To build resilient programs that handle unexpected user input, network interruptions, or file access issues, Python provides defensive structured error handling using **`try`** and **`except`** blocks.

### Common Python Built-in Exceptions

| Exception Type | Trigger Condition | Concrete Example |
| :--- | :--- | :--- |
| `ValueError` | Valid data type, but illegitimate value | `int("not_a_number")` |
| `TypeError` | Operation applied to incompatible object types | `"5" + 10` |
| `NameError` | Attempting to access an undefined identifier | `print(unassigned_variable)` |
| `ZeroDivisionError` | Divisor or modulo parameter equals zero | `100 / 0` or `100 % 0` |
| `OverflowError` | Arithmetic calculation exceeds system numerical limits | `2.0 ** 10000` |

### Catching Targeted Exceptions

A well-architected program never crashes unexpectedly. By wrapping potentially volatile operations inside a `try` block, you can intercept specific exceptions and provide graceful fallbacks:

```python
def safe_divide(num1, num2):
    """Safely divide two numbers while guarding against Type and Zero division errors."""
    try:
        result = num1 / num2
        return f"Result: {result}"
    except ZeroDivisionError:
        return "Error: Division by zero is undefined."
    except TypeError:
        return "Error: Both arguments must be numeric types (int or float)."

print(safe_divide(10, 2))      # Result: 5.0
print(safe_divide(10, 0))      # Error: Division by zero is undefined.
print(safe_divide(10, "two"))  # Error: Both arguments must be numeric types (int or float).
```

> [!WARNING]
> **Anti-Pattern: The Bare `except:` Clause**:
> Avoid writing blanket exception handlers without specifying an exception class:
> ```python
> # DANGEROUS: Catches and swallows ALL errors silently
> try:
>     run_critical_code()
> except:
>     pass
> ```
> A bare `except:` intercepts everything—including `KeyboardInterrupt` (preventing users from stopping scripts via `Ctrl+C`), `SystemExit`, and critical typographical bugs. Always specify the exact exception types you intend to handle.

## 7.7 Simulating Events & Monte Carlo Experiments

Beyond deterministic decision trees, conditional logic empowers programs to model probabilistic systems. A **Monte Carlo experiment** is an algorithmic technique that uses repeated pseudorandom sampling to estimate the probability of complex mathematical, physical, or social outcomes.

Under the **Law of Large Numbers**, as the number of independent simulation trials $N$ grows toward infinity, the empirical sample mean $\bar{X}_N$ converges almost surely to the true expected theoretical value $\mathbb{E}[X]$:

$$\lim_{N \to \infty} P\left(\left|\frac{1}{N}\sum_{i=1}^N X_i - \mu\right| < \varepsilon\right) = 1 \quad (\forall \varepsilon > 0)$$

Python's built-in `random` module provides two essential functions for generating pseudorandom numbers:
* **`random.randint(a, b)`**: Generates a discrete uniform random integer $k \in [a, b]$ such that $a \le k \le b$.
* **`random.random()`**: Generates a continuous uniform random float in the half-open interval $[0.0, 1.0)$.

### Simulation 1: The Fair Coin Toss

Consider simulating a fair coin with theoretical probability $P(\text{Heads}) = 0.5$ and $P(\text{Tails}) = 0.5$. Over thousands of trials, the ratio of heads to tails should converge toward $1.0$:

```python
import random

def simulate_coin_toss(trials=10_000):
    heads = 0
    tails = 0
    for _ in range(trials):
        # 0 represents Heads, 1 represents Tails
        if random.randint(0, 1) == 0:
            heads += 1
        else:
            tails += 1
            
    ratio = heads / tails
    print(f"Heads: {heads}, Tails: {tails}, Ratio (H/T): {ratio:.4f}")

simulate_coin_toss(10_000)
# Output: Ratio (H/T) ~ 1.0024 (converges to 1.0)
```

### Simulation 2: Multi-Region Election Modeling

Suppose Candidate A is running for office in a municipality divided into three voting districts. The candidate's independent probability of winning each district has been polled as:
* **Region 1**: $P(R_1) = 0.87$ ($87\%$)
* **Region 2**: $P(R_2) = 0.65$ ($65\%$)
* **Region 3**: $P(R_3) = 0.17$ ($17\%$)

To win the election, Candidate A must carry a majority—winning **at least 2 of the 3 regions**. What is the overall probability that Candidate A wins the election?

We model each district election as an independent Bernoulli trial:
$$r_i = \begin{cases} 1 & \text{if } U[0, 1) < p_i \\ 0 & \text{otherwise} \end{cases}$$

The election is won if:
$$\sum_{i=1}^3 r_i \ge 2$$

## Chapter Summary & Quick Reference

* **Boolean Comparators**:
  * Relational operators: `==`, `!=`, `<`, `<=`, `>`, `>=`.
  * Strings are evaluated **lexicographically** according to Unicode values (`ord()`).
  * Never confuse variable assignment (`=`) with equality checking (`==`).
* **Logical Operators & Precedence**:
  * Conjunction: `and` requires both operands to be `True`.
  * Disjunction: `or` requires at least one operand to be `True`.
  * Negation: `not` flips truth polarity.
  * Evaluation hierarchy: $\text{Comparators} \succ \text{not} \succ \text{and} \succ \text{or}$. Use parentheses to avoid ambiguity.
* **Branching Statements**:
  * Use `if` for conditional guards, `else` for exhaustive fallback, and `elif` for sequential mutual exclusion.
  * Python executes only the first matching `if` or `elif` block, skipping the remaining chain.
  * Flatten nested `if` pyramids using compound boolean expressions.
* **Divisibility & Factors**:
  * Check factors using the modulus operator: `n % i == 0`.
* **Loop Flow Control**:
  * `break` terminates loop execution immediately.
  * `continue` skips the rest of the current iteration and advances to the next cycle.
  * `for...else` / `while...else` executes its `else` block only when the loop terminates without encountering a `break`.
* **Defensive Exception Handling**:
  * Trap runtime failures (`ValueError`, `TypeError`, `ZeroDivisionError`) inside `try...except` blocks.
  * Never use bare `except:` clauses, which conceal bugs and block process signals.
* **Monte Carlo Simulations**:
  * Repeated random sampling (`random.randint`, `random.random`) approximates complex analytical probabilities through the Law of Large Numbers.
