## Introduction: Persistent State and the Physical Byte Model

In previous chapters, every program ran inside temporary memory (RAM). Variables, lists, and user input lived only while Python was running—the moment the program finished, everything in RAM vanished.

To build real-world software—such as data pipelines, web backends, or automation scripts—your programs need **persistence**: saving data to disk (like an SSD) so it survives after the script exits.

```
    Volatile Execution (RAM)                     Persistent Storage (Disk)
  ┌───────────────────────────┐                 ┌──────────────────────────┐
  │      Python Process       │                 │       File System        │
  │                           │                 │                          │
  │   variables, objects,     │  file.write()   │   data.txt               │
  │   dataframes, lists       │ ──────────────> │   [ 0x48 0x65 0x6C ... ] │
  │                           │  file.read()    │                          │
  │   (Destroyed on exit)     │ <────────────── │   temperatures.csv       │
  └───────────────────────────┘                 └──────────────────────────┘
```

### How Files Are Stored: Bytes and Text Encoding

At the operating system level, every **file** is simply a long sequence of **bytes**—numbers from `0` to `255` (each byte is 8 bits). Whether a file is an image, an audio clip, or a plain text note, on disk it's just bytes. To turn those bytes back into readable characters (like `'A'` or `'🚀'`), your program uses a **character encoding**—think of it as a translation table between letters and numbers.

The universal modern standard is **UTF-8**, which can represent every Unicode character cleanly using 1 to 4 bytes per character.

### Filesystem Hierarchies: POSIX vs. Windows

Operating systems organize files into a folder tree starting from a root location:

1. **POSIX (macOS, Linux, Unix)**:
   * Single unified root denoted by a forward slash (`/`).
   * Path separator: forward slash (`/`).
   * Example: `/Users/David/Documents/dataset.csv`.
2. **Windows**:
   * Multi-rooted system partitioned by drive volumes (e.g., `C:\`, `D:\`).
   * Path separator: backslash (`\`).
   * Example: `C:\Users\David\Documents\dataset.csv`.

In legacy Python codebases, developers manually concatenated path strings using string concatenation or `os.path.join()`. This frequently introduced escape-sequence bugs on Windows (where `\n` or `\t` in paths triggered control characters) and caused brittle, non-portable code. Python 3.4 introduced the `pathlib` module, establishing a modern, object-oriented, cross-platform standard.

## 11.1 Working with Modern Paths: `pathlib`

The built-in `pathlib` module models filesystem paths not as raw, error-prone string primitives, but as rich, first-class Python objects.

To begin working with paths, import the `Path` class:

```python
from pathlib import Path
```

### Instantiating `Path` Objects

You can construct `Path` instances through three primary mechanisms:

#### 1. From a String
```python
# POSIX style
posix_path = Path("/home/developer/projects/report.txt")

# Windows style: Always use raw string literals (r"...") to prevent escape parsing
win_path = Path(r"C:\Users\Developer\projects\report.txt")
```

#### 2. Using Class Methods
* `Path.home()`: Returns an absolute `Path` pointing to the current user's profile home directory (`/home/username` on Linux or `C:\Users\Username` on Windows).
* `Path.cwd()`: Returns an absolute `Path` representing the process's Current Working Directory.

```python
home_dir = Path.home()
current_dir = Path.cwd()

print(f"User Home: {home_dir}")
print(f"Working Dir: {current_dir}")
```

#### 3. Path Concatenation via the Division Operator (`/`)
`Path` lets you join folders and filenames cleanly using the `/` operator across any operating system:

```python
data_path = Path.home() / "analytics" / "raw_data" / "metrics.csv"
print(data_path)
```

The `/` operator handles OS-specific separator conversions automatically, eliminating manual string replacements.

### Absolute vs. Relative Paths

* **Absolute Path**: An unambiguous path originating directly from the filesystem root (`/` on Linux/macOS, `C:\` on Windows). It identifies a unique resource regardless of the process's working directory.
* **Relative Path**: A path evaluated relative to `Path.cwd()`. Converting a relative path to an absolute path can be accomplished via `.resolve()`:

```python
rel_path = Path("reports/summary.txt")
abs_path = rel_path.resolve()

print(f"Relative: {rel_path}")
print(f"Resolved Absolute: {abs_path}")
```

### Path Component Inspection

`Path` instances supply properties for decomposing and analyzing path anatomy:

```python
sample_path = Path.home() / "workspace" / "telemetry_v1.tar.gz"

print(sample_path.name)    # "telemetry_v1.tar.gz" (full filename)
print(sample_path.stem)    # "telemetry_v1.tar"    (final component without trailing extension)
print(sample_path.suffix)  # ".gz"                 (final extension component)
print(sample_path.suffixes)# [".tar", ".gz"]       (all extensions in composite archive)
print(sample_path.parent)  # Path representing immediate containing folder
print(sample_path.anchor)  # "/" on POSIX, "C:\" on Windows
```

### Path Predicates and Validation

Before reading or writing to a path, you can verify its status and type using boolean predicates:

```python
target = Path("config.json")

print(target.exists())   # True if a file or directory exists at the path
print(target.is_file())  # True strictly if the target exists and is a file
print(target.is_dir())   # True strictly if the target exists and is a directory
```

## 11.2 Common File System Operations

Beyond inspecting existing locations, `pathlib.Path` objects expose methods for creating, searching, renaming, and removing files and directories.

### Creating Directories with `mkdir()`

When creating directories in automated pipelines, intermediate folders may not yet exist, or the folder might already have been initialized on a previous run. The `mkdir()` method handles both cases gracefully:

```python
archive_dir = Path.home() / "data" / "backups" / "daily"

# Safe, idempotent directory creation
archive_dir.mkdir(parents=True, exist_ok=True)
```

* `parents=True`: Recursively creates any missing parent directories (analogous to Unix `mkdir -p`).
* `exist_ok=True`: Prevents raising a `FileExistsError` if the target folder already exists.

### Creating Empty Files with `touch()`

The `touch()` method creates an empty file at the designated location or updates the last modified timestamp if the file already exists:

```python
flag_file = archive_dir / ".complete.lock"
flag_file.touch(exist_ok=True)
```

### Iterating and Filtering Directory Contents

#### 1. Shallow Directory Listing: `iterdir()`
The `iterdir()` generator yields `Path` objects for all direct children inside a directory:

```python
target_folder = Path.cwd()

for item in target_folder.iterdir():
    kind = "DIR " if item.is_dir() else "FILE"
    print(f"[{kind}] {item.name}")
```

#### 2. Pattern Matching with `glob()` and `rglob()`
The `glob()` method searches directory contents using pattern wildcards:
* `*`: Matches zero or more arbitrary characters (e.g., `"*.py"` matches all Python scripts).
* `?`: Matches exactly one character (e.g., `"test_?.py"`).
* `[seq]`: Matches any character defined within the brackets (e.g., `"image_[0-9].png"`).

To search recursively across all nested subdirectories, use `rglob()`:

```python
project_root = Path.cwd()

# Find all Markdown documents across the entire project tree
for doc in project_root.rglob("*.md"):
    print(f"Documentation file: {doc.relative_to(project_root)}")
```

### Moving, Renaming, and Deleting

#### Renaming and Relocating Files: `replace()`
The `replace()` method renames a file or moves it to a new directory path:

```python
src = Path("draft_report.txt")
dest = Path("archive") / "final_report.txt"

# Atomically moves/renames src to dest
src.replace(dest)
```

> **Warning**: If `dest` already exists, `replace()` will overwrite it silently on POSIX systems without prompting.

#### Deleting Files and Folders
* `path.unlink(missing_ok=True)`: Permanently deletes a single file. Passing `missing_ok=True` prevents a `FileNotFoundError` if the file does not exist.
* `dir_path.rmdir()`: Deletes an empty directory. If the directory contains any files or subdirectories, Python raises an `OSError`.
* `shutil.rmtree(dir_path)`: Recursively deletes a non-empty directory and its entire subtree. Use with caution.

```python
import shutil

temp_file = Path("temp_cache.bin")
temp_file.unlink(missing_ok=True)

temp_dir = Path("scratch_dir")
if temp_dir.exists():
    shutil.rmtree(temp_dir)
```

## 11.4 Reading and Writing Plain Text Files

Operating systems keep track of every open file using a numbered ticket called a **file descriptor**, and each program is only allowed a limited number of open files at once (often around `1024` or `4096`). If a script keeps opening files without closing them, it eventually runs out of tickets and crashes with `OSError: [Errno 24] Too many open files`.

### The Context Manager (`with` Statement)

To guarantee that files are always closed automatically when you're done—even if an error happens—Python provides the `with` statement (called a **context manager**):

```python
file_path = Path("notes.txt")

with file_path.open(mode="r", encoding="utf-8") as file:
    content = file.read()
# The file is automatically closed here, even if an error occurred inside!
```

Behind the scenes, `with` runs two special steps: `__enter__()` opens the file and hands it to you, and `__exit__()` closes it cleanly as soon as the indented block finishes.

### File Modes Summary

| Mode | Name | Description | Pointer Position | Overwrites? |
| :--- | :--- | :--- | :--- | :--- |
| `"r"` | Read | Opens existing file for reading. Raises `FileNotFoundError` if missing. | Beginning | No |
| `"w"` | Write | Opens for writing. Creates file if missing; clears existing contents if present. | Beginning | **Yes** |
| `"a"` | Append | Opens for writing. Creates file if missing; adds new data to the end. | End | No |
| `"r+"`| Read/Write | Updates existing file without clearing it first. | Beginning | In-place |

### Reading Techniques & Memory Usage

How you read a file determines how much memory (RAM) your program uses:

#### 1. Whole File Slurp: `file.read()`
Loads the entire file into memory as one big string (memory grows with file size):

```python
with file_path.open(mode="r", encoding="utf-8") as f:
    full_text = f.read()
```
*Best for*: Small configuration files, JSON payloads, or templates under a few megabytes.

#### 2. Line List Loading: `file.readlines()`
Loads all lines into memory at once as a Python list of strings (also grows with file size):

```python
with file_path.open(mode="r", encoding="utf-8") as f:
    lines = f.readlines()
```

#### 3. Streaming Line-by-Line Iteration
Reads one line at a time, so memory usage stays tiny no matter how huge the file is:

```python
with file_path.open(mode="r", encoding="utf-8") as f:
    for line in f:
        # Each line includes trailing newline character '\n'
        print(line.rstrip("\r\n"))
```
*Best for*: Large datasets, multi-gigabyte log archives, and memory-constrained production microservices.

### Writing Plain Text Files

Writing to a text file requires specifying `mode="w"` (to overwrite/create) or `mode="a"` (to append):

```python
output_path = Path("greeting.txt")

# Writing single strings
with output_path.open(mode="w", encoding="utf-8") as f:
    f.write("Line 1: Foundations of Python I/O\n")
    f.write("Line 2: Built-in safety with context managers\n")

# Appending lines
with output_path.open(mode="a", encoding="utf-8") as f:
    f.write("Line 3: Appended without overwriting\n")

# Writing an iterable collection of strings
bulk_lines = ["Entry A\n", "Entry B\n", "Entry C\n"]
with output_path.open(mode="w", encoding="utf-8") as f:
    f.writelines(bulk_lines)
```

## 11.5 Structured Tabular Data with the `csv` Module

Text files often store spreadsheet-style tables made of rows (records) and columns (fields). The standard format for sharing tables across platforms and databases is **CSV (Comma-Separated Values)**.

Python provides the standard library module `csv` to parse quotes, commas, escapes, and newlines accurately.

### List-Based Processing: `csv.reader` and `csv.writer`

#### Writing Matrix Rows (`csv.writer`)
When opening a file for writing with `csv`, always specify `newline=""` to prevent blank lines from being injected on Windows platforms:

```python
import csv
from pathlib import Path

csv_path = Path("temperatures.csv")
daily_readings = [
    ["Day", "High_C", "Low_C"],
    ["Monday", 28, 17],
    ["Tuesday", 31, 19],
    ["Wednesday", 25, 14],
]

with csv_path.open(mode="w", encoding="utf-8", newline="") as f:
    writer = csv.writer(f)
    writer.writerows(daily_readings)
```

#### Reading Matrix Rows (`csv.reader`)
Values parsed by `csv.reader` are returned exclusively as `str` tokens. Numerical values must be explicitly coerced:

```python
with csv_path.open(mode="r", encoding="utf-8") as f:
    reader = csv.reader(f)
    header = next(reader)  # Skip header row ['Day', 'High_C', 'Low_C']
    
    for row in reader:
        day = row[0]
        high = float(row[1])
        low = float(row[2])
        print(f"{day}: High={high}°C, Low={low}°C")
```

### Dictionary-Based Processing: `DictReader` and `DictWriter`

When datasets feature an explicit header row, dictionary readers and writers provide self-documenting code and immunity to column ordering variations.

#### Reading Datasets as Dictionaries (`csv.DictReader`)
`DictReader` reads the first row to establish dictionary keys, mapping each subsequent row into a Python dictionary:

```python
employee_file = Path("employees.csv")

with employee_file.open(mode="r", encoding="utf-8") as f:
    reader = csv.DictReader(f)
    print(f"Detected columns: {reader.fieldnames}")
    
    for record in reader:
        print(f"Employee: {record['name']} | Dept: {record['department']}")
```

#### Writing Dictionaries to CSV (`csv.DictWriter`)
`DictWriter` requires an explicit `fieldnames` sequence and must invoke `writer.writeheader()` before emitting rows:

```python
inventory_path = Path("inventory.csv")
items = [
    {"sku": "A101", "product": "Mechanical Keyboard", "quantity": 14, "price": 89.99},
    {"sku": "B204", "product": "Ergonomic Mouse", "quantity": 28, "price": 49.50},
    {"sku": "C305", "product": "USB-C Dock", "quantity": 8, "price": 129.00},
]

fieldnames = ["sku", "product", "quantity", "price"]

with inventory_path.open(mode="w", encoding="utf-8", newline="") as f:
    writer = csv.DictWriter(f, fieldnames=fieldnames)
    writer.writeheader()
    writer.writerows(items)
```

## 11.7 Chapter Summary & Best Practices

1. **Object-Oriented Paths**: Use `pathlib.Path` exclusively instead of brittle string concatenation or legacy `os.path`. The `/` operator standardizes separator resolution across operating systems.
2. **Context Managers for I/O**: Never open a file without a `with` statement. Context managers enforce deterministic teardown ($\mathcal{F} \to \emptyset$), guarding against file descriptor exhaustion.
3. **Mandatory UTF-8 Encodings**: Explicitly pass `encoding="utf-8"` to all `open()` calls to protect software against operating system default encoding discrepancies.
4. **Memory-Safe Streaming**: For large or unpredictable file sizes, iterate over lines using `for line in file:`. This streams records with an $\mathcal{O}(1)$ memory buffer rather than slurping the entire dataset into memory.
5. **Structured CSV Pipelines**: When tabular data includes header labels, use `csv.DictReader` and `csv.DictWriter`. Always set `newline=""` when writing CSV files to prevent unintended blank lines across operating systems.
