Once you move past your first single-agent script, writing raw HTTP payloads, JSON tool schemas, and multi-turn message arrays by hand gets tedious fast. **AI Agent Frameworks** give us reusable building blocks—tool decorators, memory connectors, multi-agent handoffs, and state managers—so we can focus on business logic instead of boilerplate.

By the way, it helps to separate *two* different layers in the ecosystem: **code-first agent SDKs** (where your Python process owns the reasoning loop) and **stateful agent runtimes** (where a managed service persists conversation threads, messages, and runs for you).

---

## Why Agent Frameworks Go Beyond Traditional AI SDKs

Traditional AI libraries help you call a model for personalization, text generation, or classification. **Agentic Frameworks** add three higher-level capabilities:

1. **Use Modular Components**: Ready-made `@tool` decorators, input parsers, prompt templates, and memory stores let teams prototype in hours instead of weeks.
2. **Leverage Collaborative Tools**: Assign distinct roles to specialized agents (`dataretrieval` $\rightarrow$ `dataanalysis`, or `planner` $\rightarrow$ `executor`) and pass structured results between them.
3. **Learn in Real Time**: Wire feedback loops into the runtime so agents adapt their behavior dynamically from user ratings and environment signals.

---

## Code-First Agent SDKs vs. Stateful Thread/Run Runtimes

When architecting a new agent application, you will usually pick between—or combine—these two patterns:

| Dimension | Code-First Agent SDK (e.g., `LangGraph` / Python `@tool` SDK) | Stateful Thread/Run Runtime |
| :--- | :--- | :--- |
| **Core Primitives** | `Agent(name, instructions, tools)`, `@tool` functions, `StateGraph` | `Agent`, `Thread`, `Message`, `create_and_process_run()` |
| **Execution Control** | Full control over every LLM call, retry, and custom middleware | Runtime executes server-side tool loops and manages thread history |
| **Multi-Agent Pattern** | Explicit Python chaining (`plan = planner.run(...); executor.run(plan)`) | Microservice-style agent endpoints with built-in file/code tools |
| **Best Use Case** | Rapid iteration, custom reasoning loops, portable open-source apps | Long-lived multi-turn sessions with externalized state & RBAC |

```python
# Code-First Sequential Collaboration Pattern
retrieval_result = agent_retrieve.run("Retrieve sales data for Q4")
analysis_result = agent_analyze.run(f"Analyze this data: {retrieval_result}")
```

In a **Stateful Thread/Run Runtime**, conversations are modeled as persistent `Thread` objects. Each user turn appends a `Message`, and `create_and_process_run(thread_id, agent_id)` invokes tools like `get_specials()` or `get_item_price()` automatically before appending the assistant's reply back to the thread.
