In a notebook, you can eyeball an agent's print statements and call it a day. In production, an agent that silently loops five times or hallucinates on an edge case burns real money and user trust. **Observability and Evaluation** turn your "black box" agent into a transparent **"glass box"** you can debug, measure, and afford to run.

---

## Traces, Spans & The 7 Production Signals

Modern observability tools (**OpenTelemetry** and open-source **Langfuse**) model every agent execution as a **Trace** (the full end-to-end task) composed of nested **Spans** (each LLM call, retrieval step, or tool execution) tagged with attributes like `user_id`, `session_id`, and `model_version`.

| Metric / Signal | What It Measures | Production Action |
| :--- | :--- | :--- |
| **Latency ($P_{50}, P_{95}$)** | End-to-end and per-span response time | Parallelize independent tool calls or route to faster SLMs |
| **Token & API Costs** | Expense per agent run | Detect runaway loops; apply caching and complexity routing |
| **Request Errors** | Failed LLM or tool calls | Trigger exponential backoff or provider fallbacks (`A -> B`) |
| **Explicit Feedback** | Thumbs up/down, 1–5 star ratings | Alert on negative spikes and add failures to offline eval sets |
| **Implicit Feedback** | Immediate query rephrasing, retries | Catch silent dissatisfaction even when users don't click 👎 |
| **Task Accuracy** | Ground-truth or rubric pass rate | Gate CI/CD releases before shipping prompt/model changes |
| **Automated Evals** | LLM-as-a-Judge, **RAGAS**, **LLM Guard** | Score faithfulness, helpfulness, and prompt-injection safety |

## Offline vs. Online Evaluation & Cost Control

**Offline Evaluation** runs repeatable golden datasets (such as GSM8K or curated expense-claim test cases) in CI/CD before deployment. **Online Evaluation** monitors live traffic for model drift and unexpected queries, feeding real-world failures right back into the offline test set:

$$\text{Evaluate Offline} \rightarrow \text{Deploy} \rightarrow \text{Monitor Online} \rightarrow \text{Collect Failures} \rightarrow \text{Refine}$$

To keep production token bills predictable, combine three cost-control levers:
1. **Small Language Models (SLMs)** (`gemini-2.5-flash-lite`) for intent classification and extraction.
2. **Complexity Router Models** to send simple queries to SLMs and complex reasoning to larger models (`gemini-2.5-flash`).
3. **Response Caching** for frequent FAQs so repeated queries cost `0` tokens.
