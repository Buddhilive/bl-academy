To switch a Colab notebook onto a free GPU when training vision or language models:

1. Open the notebook in Google Colab and click **Connect** in the top-right corner.
2. From the top menu, select **Runtime** → **Change runtime type**.
3. Choose **T4 GPU** under Hardware Accelerator and click **Save**.

> **Tip:** Free T4 GPU sessions are ideal for training CNNs and fine-tuning Transformers, while CPU runtimes are faster to start for Symbolic AI, Reinforcement Learning, and Genetic Algorithms. Always disconnect or switch back to CPU when you don't need a GPU so you preserve your daily free quota.

## Getting Your Free Google AI Studio API Key (`GEMINI_API_KEY`)

Later in this course (and throughout our upcoming Generative AI, MCP, and AI Agents tracks), we'll run live Large Language Model experiments using the official `google-genai` Python SDK. Google AI Studio provides a generous **Free Tier** so you can prototype prompts without entering a credit card.

### Step 1: Generate the Key
1. Visit [aistudio.google.com/apikey](https://aistudio.google.com/apikey) and sign in with your Google account.
2. Click **Create API Key** and select or create a Google Cloud project when prompted.
3. Copy the generated key string immediately, never commit API keys directly into code or public Git repositories.

### Step 2: Store It Safely in Colab Secrets
1. Open your Google Colab notebook and click the **Secrets (key icon)** in the left sidebar.
2. Click **Add new secret**.
3. Set the **Name** to `GEMINI_API_KEY` and paste your key into **Value**.
4. Toggle **Notebook access** to **On**.

### Step 3: Load It in Python
Inside any Colab cell, load your key securely via `google.colab.userdata`:

```python
from google.colab import userdata
from google import genai

api_key = userdata.get("GEMINI_API_KEY")
client = genai.Client(api_key=api_key)

response = client.models.generate_content(
    model="gemini-2.5-flash",
    contents="Explain what a neural network is in two sentences.",
)
print(response.text)
```

## Understanding Model Memory & Precision

Why do we care about CPU RAM vs. T4 GPU VRAM? Think of a neural network's parameters (its learned weights) like numbers stored in a spreadsheet: the more numbers you have and the more decimal precision each number uses, the more memory the spreadsheet takes. In standard 32-bit floating point (`FP32`), each parameter consumes $4$ bytes. In half precision (`FP16`), it consumes $2$ bytes, and in 8-bit integer quantization (`INT8`), it consumes $1$ byte:

$$\text{Memory (GB)} = \frac{N_{\text{params}} \times B_{\text{bytes/param}}}{1024^3}$$

Here, $N_{\text{params}}$ is the total number of parameters in the model, $B_{\text{bytes/param}}$ is how many bytes each number takes (`4` for FP32, `2` for FP16), and dividing by $1024^3$ converts bytes into gigabytes (GB). Let's run a quick pure-Python memory estimator (in Colab or your local Python environment) to see which models fit comfortably inside a free 16 GB T4 GPU.

**Model VRAM Footprint Estimator**

```python
T4_VRAM_GB = 16.0
BYTES_PER_GB = 1024 ** 3

models = [
    ("ResNet-50", 25.6e6),
    ("BERT-Base", 110.0e6),
    ("GPT-2 Large", 774.0e6),
    ("7B Open LLM", 7000.0e6),
]

print(f"=== Colab Free T4 GPU ({T4_VRAM_GB} GB VRAM) Capacity Check ===")
for name, params in models:
    fp32_gb = (params * 4) / BYTES_PER_GB
    fp16_gb = (params * 2) / BYTES_PER_GB
    fits_fp16 = fp16_gb <= T4_VRAM_GB
    print(f"{name} ({params/1e6:.1f}M params): FP32={fp32_gb:.2f} GB | FP16={fp16_gb:.2f} GB | Fits T4={fits_fp16}")
```

**Expected Output:**

```text
=== Colab Free T4 GPU (16.0 GB VRAM) Capacity Check ===
ResNet-50 (25.6M params): FP32=0.10 GB | FP16=0.05 GB | Fits T4=True
BERT-Base (110.0M params): FP32=0.41 GB | FP16=0.20 GB | Fits T4=True
GPT-2 Large (774.0M params): FP32=2.88 GB | FP16=1.44 GB | Fits T4=True
7B Open LLM (7000.0M params): FP32=26.08 GB | FP16=13.04 GB | Fits T4=True
```
