## Choosing Cloud Compute & Low-Code vs. SDK Trade-Offs

Before launching a training job, you need to pick the right compute profile:

| Compute Choice | Characteristics | Best Used For |
| :--- | :--- | :--- |
| **CPU** | Fast single-thread clock speed, lower cost, lower concurrency | Tabular data, classical ML, AutoML on small/medium datasets |
| **GPU** | Massively parallel cores, higher cost | Deep learning, CNNs, Transformers |
| **Dedicated Instance** | Non-interruptible; guaranteed completion | Long production jobs that cannot be restarted |
| **Spot / Preemptible** | Interruptible spare capacity at steep discounts | Short, checkpointed experiments |

Low-code AutoML excels at rapid POC validation, whereas programmatic SDK pipelines (covered in Lesson 19) shine when you need automated, repeatable CI/CD production workflows.

## The Clinical Heart Failure Dataset (299 Patients, 13 Columns)

Cardiovascular diseases account for 31% of deaths globally. Using the 299-patient **Heart Failure Clinical Records** dataset, we predict the boolean target `DEATH_EVENT` from 12 clinical features:

| Feature | Type | Clinical Meaning |
| :--- | :--- | :--- |
| `age`, `sex`, `smoking`, `diabetes` | Numeric / Boolean | Patient demographics and risk factors |
| `anaemia`, `high_blood_pressure` | Boolean | Red blood cell deficit and hypertension |
| `ejection_fraction` | Numeric (%) | Percentage of blood leaving the heart per contraction |
| `serum_creatinine`, `serum_sodium` | Numeric | Kidney function & blood electrolyte levels |
| `creatinine_phosphokinase`, `platelets` | Numeric | CPK enzyme and blood platelet counts |
| `time` | Numeric (days) | Clinical follow-up period |

Open-source **FLAML** (`flaml.AutoML`) searches across Logistic Regression, Random Forests, XGBoost, and LightGBM optimizing `roc_auc`, then **Gradio** wraps the winning model in a live web form and REST API.
